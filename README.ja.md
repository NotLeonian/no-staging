# no-staging

[English](README.md)

`no-staging` は、Git リポジトリで作業するエージェントに、作業ツリーで加えた変更をステージしないよう指示する Codex スキルです。

## 概要

このスキルを有効にすると、エージェントは作業ツリー内のファイルを作成、編集、移動、削除できますが、Git インデックスを意図的に変更するコマンドは実行しません。

作業を終えるときには、追加、変更、移動、削除したファイルを報告し、それらをステージしていないことを明記します。

## 動作

スキルが有効な間、エージェントは次の規則に従います。

- ファイルをステージしません。
- `git add`、`git stage`、`git commit`、`git mv`、`git rm` など、Git インデックスを意図的に変更するコマンドを実行しません。
- 作業を始める前からステージされている変更は、そのまま残します。
- 作業ツリー内のファイルは通常どおり作成、編集、移動、削除できます。
- `git status`、`git diff`、`git diff --stat`、`git ls-files` など、状態や差分を調べる Git コマンドは使用できます。
- タスクを完了するためにステージする必要がある場合は作業を止め、明示的な許可を求めます。
- 最後に、追加、変更、移動、削除したファイルと、それらをステージしていないことを報告します。

一時的にステージしてから元に戻す操作も行いません。

## インストール

リポジトリを取得し、その絶対パスをローカルのマーケットプレイスとして登録してから、プラグインをインストールします。

```console
git clone https://github.com/NotLeonian/no-staging.git
codex plugin marketplace add /absolute/path/to/no-staging
codex plugin add no-staging@no-staging
```

インストールした後は、新しい Codex スレッドを開始してスキルを読み込んでください。

スキルだけを使う場合は、`SKILL.md` をローカルの Agent Skills ディレクトリへコピーします。

```console
mkdir -p "$HOME/.agents/skills/no-staging"
cp /absolute/path/to/no-staging/skills/no-staging/SKILL.md "$HOME/.agents/skills/no-staging/SKILL.md"
```

## 使い方

Git リポジトリでの作業を依頼するときに、スキルを指定します。

```text
$no-staging

必要な変更を加えてください。ただし、どの変更もステージしないでください。
```

互換性のあるホストでは、ファイルを追加、変更、移動、削除してもステージしないよう明示した Git タスクに対して、このスキルが自動的に選ばれる場合もあります。

## このスキルが保証しないこと

このスキルはエージェントへの指示であり、ステージングを技術的に遮断する仕組みではありません。

- Git フック、sandbox、権限を管理する仕組み、OS のアクセス制御ではありません。
- ホストがスキルを読み込み、エージェントが指示に従っている間だけ作用します。
- ユーザー、IDE、バックグラウンドのプロセス、別のエージェント、別のセッションが Git インデックスを変更することは防げません。
- スキルを有効にする前からステージされている変更は、元に戻したりステージから外したりしません。
- 作業ツリー内でファイルを作成、編集、移動、削除することは許可します。ファイルを保護したり、バックアップを作成したりするスキルではありません。
- Git 以外のバージョン管理システムには適用しません。また、ステージングと関係のない書き込みを広く禁止するものでもありません。
- Git 全体を安全に操作するためのポリシーではありません。ステージングと関係のない操作には、ホストが定める別の指示や安全策が適用されます。
- 外部ツールが予期せず Git インデックスを変更する場合、このスキルだけではその変更を防げません。
- ステージしなければ完了できないタスクでは、ユーザーから明示的な許可を得るまで作業を進められません。

読み取り専用として扱われる Git コマンドでも、Git の設定によっては FSMonitor、filter、外部 diff、pager などの補助プログラムを起動する場合があります。また、ファイルの内容をステージしなくても、インデックスのメタデータを更新する場合があります。このスキルは、意図したステージングの状態を保つためのものであり、`.git/index` の内容が一切変わらないことや、状態を調べるコマンドに副作用がないことまでは保証しません。そのような保証が必要な場合は、別の技術的な制御、信頼できる実行ポリシー、または `codex-read-only-approver` のような補助的な仕組みを併用してください。

最後に「ファイルをステージしていない」と報告しても、それはエージェント自身の操作について述べているだけです。別の要因によってステージされた変更がないことまでは証明しません。

## 確認する

作業の前後でステージングの状態を調べます。

```console
git status --short
git diff --cached --name-only
```

作業を始める前からステージされている変更がある場合、2 番目のコマンドの出力は空になりません。その場合は、作業の前後で出力を比較してください。これらのコマンドは状態を調べるための例であり、ステージングを強制的に防ぐものではありません。

## テスト

追加のパッケージをインストールせずに、リポジトリのテストを実行できます。

```console
python3 -B -m unittest discover -s tests -p 'test_*.py' -v
```

テストでは、JSON ファイルを解析できること、プラグインとマーケットプレイスのメタデータが一致すること、ホストがスキルを検出できる構成になっていること、`no-staging` の主要な指示が残っていること、Markdown 文書内の相対リンク先が存在することを確認します。テストの対象はリポジトリの構成と静的な指示です。エージェントの動作は再現しないため、エージェントがスキルに従うことまでは証明しません。

GitHub Actions は、push と pull request のたびに同じコマンドを実行します。
